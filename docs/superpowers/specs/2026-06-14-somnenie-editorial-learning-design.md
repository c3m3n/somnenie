# ТЗ: визуальная система Somnenie

Дата: 2026-06-14  
Статус: черновик для дизайн-проработки  
Проект: Somnenie / Nutrio app  
Тип работы: дизайн-концепция и UX-спецификация перед внедрением

## 1. Цель

Сформировать новый визуальный язык приложения Somnenie: доказательная обучающая платформа, которая ощущается не как админка курсов и не как wellness-приложение, а как mobile-first learning machine с editorial-характером.

Новый дизайн должен:

- сделать первый экран сильным и запоминающимся;
- сохранить ощущение доказательности и серьёзности;
- на телефоне вести пользователя к одному понятному учебному действию;
- поддержать цикл: понять идею -> применить -> проверить -> закрепить -> вернуться к слабым местам;
- не превращать процесс обучения в декоративный промо-сайт.

## 2. Продуктовое позиционирование

Somnenie - это не:

- трекер питания;
- медицинский советчик;
- маркетплейс курсов;
- публичная платформа авторов;
- набор длинных статей.

Somnenie - это:

- учебный атлас по сложной теме;
- короткие интерактивные сессии;
- доказательные материалы с источниками и границами применимости;
- тренажёр слабых мест;
- личный прогресс без социального давления.

Базовая формула интерфейса:

> Один экран. Одна идея. Одно действие. Один следующий шаг.

## 3. Референсы и что из них брать

### 3.1 Brilliant

Брать:

- learn by doing;
- визуальное объяснение перед длинной теорией;
- короткую ежедневную сессию;
- вопросы как основной двигатель понимания;
- отслеживание пробелов и возврат к ним.

Не брать:

- детскую мультяшность;
- чрезмерную геймификацию;
- визуальную легкомысленность для медицински чувствительной темы.

### 3.2 Elixir Studio

Брать:

- много воздуха;
- один сильный тезис на первом экране;
- спокойную уверенность;
- лаконичные метрики;
- минимальную навигацию.

Не брать:

- слишком пустой первый экран без учебного действия;
- эффектность, которая требует долгого ожидания или анимации.

### 3.3 Nextec

Брать:

- нумерацию 01/02/03/04;
- плитки режимов;
- структуру процесса;
- ощущение функционального продукта;
- хороший перенос на мобильный экран.

Не брать:

- корпоративную sales-подачу;
- перегруз сервисными блоками;
- cookie/banner-подобные перекрытия важного контента.

### 3.4 Editorial / portfolio references

Брать:

- крупную типографику;
- асимметричную композицию;
- чёрно-белую графику;
- один яркий оранжево-красный акцент;
- ощущение разворота или главы.

Не брать:

- декоративность ради декоративности;
- desktop-only композиции, которые ломаются на телефоне;
- иллюстрации, которые конкурируют с учебным заданием.

## 4. Главный дизайн-принцип

Дизайн должен соединить три слоя:

1. Editorial identity  
   Обложка, маршрут, главы, иллюстрации, крупная типографика.

2. Learning interaction  
   Вопрос, выбор, обратная связь, фиксация вывода, weak spots.

3. Evidence trust  
   Источники, границы применимости, медицинская оговорка, спокойный тон.

Если экран учебный, то interaction важнее editorial. Если экран навигационный или вступительный, editorial может быть сильнее.

## 5. Информационная архитектура

Существующие зоны приложения сохраняются:

- Onboarding / первый визит;
- Today;
- Atlas;
- Station;
- Memory;
- Journal / Profile;
- Remediation.

Новый дизайн не должен добавлять admin/editor/creator UI.

## 6. Mobile-first структура

Телефон - основной сценарий проверки дизайна.

На мобильном первый экран строится так:

1. Верхняя строка: знак Somnenie, меню.
2. Крупный заголовок текущей учебной сессии.
3. Короткое объяснение, зачем этот шаг.
4. Плитки процесса:
   - 01 Идея;
   - 02 Выбор;
   - 03 Разбор;
   - 04 Вывод.
5. Карточка текущего блока.
6. Primary CTA: начать сессию.
7. Мини-прогресс и медицинская оговорка.

На телефоне не пытаться ужать desktop-плакат. Большая иллюстрация становится знаком главы: обрезается, уходит вверх/вбок или используется как маленький визуальный якорь.

## 7. Экран: Onboarding / первый визит

Назначение: дать сильное первое впечатление и быстро перевести пользователя в первый блок.

Содержание:

- бренд Somnenie;
- главный заголовок: "Построй понимание питания" или "Питание без мифов";
- подзаголовок: доказательный маршрут, короткие интерактивные сессии, слабые места;
- 4 плитки процесса:
  - Understand / Идея;
  - Apply / Действие;
  - Check / Проверка;
  - Anchor / Вывод;
- CTA: "Начать первый блок";
- вторичная ссылка: "Открыть маршрут";
- медицинская оговорка.

Визуально:

- много воздуха;
- тёплый светлый фон;
- крупная чёрная типографика;
- оранжево-красный CTA или акцент;
- простая линейная иллюстрация темы.

## 8. Экран: Today

Назначение: основной вход после onboarding.

Today не должен быть мини-дашбордом со всем сразу. Он отвечает на вопрос:

> Что мне сделать сейчас?

Содержание:

- текущая учебная сессия;
- предполагаемая длительность;
- статус блока;
- один primary CTA;
- мини-прогресс маршрута;
- если есть weak spots - мягкое предложение тренировки;
- если зачёт провален - CTA на разбор ошибок.

Варианты состояний:

- новый пользователь: начать M01;
- блок начат: продолжить с места;
- теория пройдена: перейти к проверке;
- зачёт провален: разобрать ошибки;
- есть due reviews: тренировка памяти;
- курс завершён: открыть конспект/повтор.

Визуально:

- Elixir-like воздух;
- один крупный заголовок;
- 1-2 функциональные карточки максимум;
- плитки 01/02/03/04 могут показывать место в сессии.

## 9. Экран: Atlas

Назначение: показать маршрут курса как учебный атлас, а не таблицу модулей.

Содержание:

- название курса;
- фазы курса;
- блоки внутри фаз;
- текущий блок;
- заблокированные блоки;
- зачёты и статусы.

Визуально:

- Nextec-подобная нумерация;
- фазы как крупные главы;
- блоки как плитки;
- цветовые акценты для состояний:
  - доступен;
  - в процессе;
  - нужен зачёт;
  - зачёт не сдан;
  - сдан;
  - закрыт.

На desktop можно использовать широкую сетку. На mobile фазы идут вертикально, блоки становятся компактными плитками.

## 10. Экран: Station

Station - главный учебный экран. Он должен быть ближе к Brilliant, чем к статье.

Структура станции:

1. Understand  
   Тезис, схема, короткое объяснение.

2. Apply  
   Маленькое действие или пример.

3. Check  
   Вопросы и зачёт.

4. Anchor  
   Записать вывод своими словами.

Важное правило:

> Теория не должна быть единственным первым действием. Пользователь должен как можно быстрее столкнуться с вопросом или выбором.

Визуально:

- шаги 01/02/03/04 видны как рельс или табы;
- иллюстрация помогает понять тезис;
- вопрос и варианты имеют максимальную читаемость;
- декоративные элементы уходят на второй план во время выбора ответа.

## 11. Экран: Check / Quiz

Назначение: проверить понимание без визуального шума.

Требования:

- один вопрос на экране;
- крупный текст вопроса;
- варианты ответа как большие tap-targets;
- мгновенная обратная связь;
- после ошибки объяснить, почему неверно;
- сохранить ошибку как weak spot;
- не использовать сложные фоновые композиции.

На mobile:

- варианты ответа занимают полную ширину;
- никакого мелкого текста в вариантах;
- CTA и статус не перекрывают вопрос;
- после ответа показывается короткое объяснение и следующий шаг.

## 12. Экран: Memory

Назначение: короткий тренажёр слабых мест.

Содержание:

- количество вопросов сегодня;
- один вопрос;
- варианты или self-check;
- результат;
- когда вернётся вопрос.

Визуально:

- может быть темнее/контрастнее, как "режим памяти";
- минимум навигации;
- один фокус;
- графика используется как атмосфера, не как украшение вокруг каждого вопроса.

## 13. Экран: Remediation

Назначение: превратить ошибку в понятное действие.

Содержание:

- вопрос, где была ошибка;
- выбранный ответ;
- правильная идея;
- почему это важно;
- ссылка на связанный материал;
- CTA: открыть материал или повторить зачёт.

Визуально:

- error state не должен быть агрессивным;
- использовать разбор как "исследовательскую карточку";
- показать, что ошибка стала частью обучения.

## 14. Экран: Journal / Profile

Назначение: личный конспект и состояние обучения.

Содержание:

- прогресс;
- сохранённые выводы;
- weak spots;
- профиль/цель;
- экспорт/сброс данных.

Визуально:

- больше archive/evidence;
- выводы как заметки;
- можно использовать разворотную editorial-композицию;
- destructive actions должны быть визуально отделены от учебного контента.

## 15. Evidence layer

Для нутрициологии важно показывать доверие.

В дизайне должны быть предусмотрены:

- карточка источника;
- уровень уверенности, если есть в данных;
- границы применимости;
- medical disclaimer;
- source gaps, если материал требует проверки.

Важно: источники не должны перегружать первый экран. Они появляются там, где пользователь изучает тезис или проверяет спорную идею.

## 16. Визуальная система

### 16.1 Цвет

Базовая палитра:

- Ink: почти чёрный `#171717`;
- Paper: тёплый светлый фон `#fbefe9` или близкий;
- White: `#fffdf8`;
- Accent: оранжево-красный `#d64b3c` / `#ef4b26`;
- Teal: глубокий сине-зелёный для вторичных состояний;
- Blue: мягкий синий для нейтральных учебных плиток;
- Muted: серо-тёплый текст.

Не использовать:

- wellness-зелёную однотонность;
- glossy gradients;
- много фиолетового;
- декоративные glow/orb эффекты.

### 16.2 Типографика

Нужны два уровня:

- display sans для крупных заголовков;
- mono или condensed/technical style для labels, нумерации, статусов.

Правила:

- заголовки могут быть очень крупными на intro/atlas;
- внутри карточек и quiz не использовать hero-size;
- не сжимать буквы отрицательным letter-spacing в мелком тексте;
- на mobile длинные русские слова должны переноситься без обрезания.

### 16.3 Иллюстрации

Стиль:

- чёрно-белая линейная графика;
- научно-биологические мотивы, но без медицинской псевдонаучности;
- оранжевые точки как маркеры внимания;
- иллюстрация должна объяснять или маркировать главу.

Для v1 не нужен уникальный рисунок для каждого блока. Достаточно:

- 1 главный знак курса;
- 6 знаков фаз;
- 3-4 универсальных паттерна для station/memory/evidence.

### 16.4 Плитки и нумерация

Использовать нумерацию как системный элемент:

- 01 Идея;
- 02 Действие;
- 03 Проверка;
- 04 Вывод.

Плитки должны быть кликабельными только если это действительно действие. Не делать декоративные карточки, которые выглядят как кнопки.

## 17. Motion

Motion допустим, но не обязателен для первого релиза.

Если добавлять:

- мягкое появление плиток;
- прогресс между шагами;
- micro-feedback после ответа;
- уважать `prefers-reduced-motion`.

Не добавлять:

- долгие загрузочные анимации;
- scroll-jacking;
- эффекты, которые мешают чтению или тесту.

## 18. Доступность

Обязательные требования:

- контраст текста не ниже WCAG AA;
- все интерактивные элементы доступны с клавиатуры;
- tap-targets на mobile не меньше 44px;
- focus-visible заметен;
- иллюстрации декоративные получают пустой `alt`;
- важные схемы получают текстовую альтернативу;
- цвет не является единственным способом передать статус.

## 19. Технические ограничения внедрения

Текущий проект - React/Vite PWA.

Существующие маршруты и зоны должны сохраняться:

- `today`;
- `atlas`;
- `memory`;
- `journal`;
- `station/:moduleId/:step`;
- `remediation/:moduleId`.

Дизайн должен внедряться поверх текущей архитектуры, без переписывания контентной модели.

Первый этап желательно делать как UI/theme pass:

- обновить layout shell;
- обновить Today;
- обновить Onboarding;
- обновить Atlas;
- затем Station.

Station и quiz трогать осторожнее, потому что там выше риск повредить учебный UX.

## 20. Критерии приёмки дизайна

Дизайн считается удачным, если:

- на desktop первый экран выглядит выразительно и не похож на типовую LMS;
- на mobile первый экран не превращается в ужатый плакат;
- пользователь сразу видит следующий учебный шаг;
- quiz остаётся читаемым и быстрым;
- маршрут курса понятен без объяснений;
- медицинская оговорка присутствует, но не доминирует;
- стиль поддерживает тему доказательности, а не wellness-маркетинг;
- все ключевые экраны работают без горизонтального скролла на 390px ширины;
- текст не перекрывает иллюстрации;
- интерактивные элементы визуально отличимы от декоративных плиток.

## 21. Предлагаемый порядок макетов

1. Mobile Today / first session.
2. Desktop Today / first session.
3. Mobile Station: Understand + Check.
4. Desktop Station: Understand + Check.
5. Mobile Atlas.
6. Desktop Atlas.
7. Memory trainer.
8. Remediation.
9. Journal/Profile.

## 22. Предлагаемый порядок внедрения

1. Создать дизайн-токены:
   - цвета;
   - типографика;
   - spacing;
   - border/shadow;
   - responsive breakpoints.

2. Обновить shell:
   - mobile nav;
   - topbar;
   - базовые страницы.

3. Сделать новый Today:
   - mobile-first;
   - один next action;
   - плитки процесса.

4. Сделать новый Onboarding:
   - editorial intro;
   - CTA в первый блок;
   - оговорка.

5. Сделать Atlas:
   - фазы как главы;
   - блоки как numbered tiles;
   - состояния доступа.

6. После проверки перейти к Station:
   - 01/02/03/04 rail;
   - улучшить визуальную структуру;
   - сохранить читаемость Markdown.

7. Затем Memory и Remediation.

## 23. Риски

### Риск: стиль красивый, но мешает учёбе

Митигировать:

- quiz и memory делать более спокойными;
- декоративную графику убирать в момент ответа;
- проверять mobile-first.

### Риск: иллюстраций нужно слишком много

Митигировать:

- начать с ограниченного набора фазовых иллюстраций;
- использовать универсальные SVG-паттерны;
- не обещать уникальную графику на каждый блок в v1.

### Риск: приложение станет похоже на лендинг

Митигировать:

- каждый экран должен иметь рабочий CTA;
- Today всегда показывает следующий шаг;
- Station всегда ведёт к действию или проверке.

### Риск: русские заголовки ломают композицию

Митигировать:

- проектировать на реальном русском тексте;
- проверять самые длинные названия модулей;
- использовать адаптивные размеры без viewport-scaling шрифтов.

## 24. Итоговое направление

Рекомендуемое направление:

> Editorial learning machine: Elixir-like воздух + Nextec-like процесс и плитки + Brilliant-like интерактивная учебная сессия.

Коротко:

- не LMS;
- не wellness;
- не промо-сайт;
- мобильный учебный атлас с интерактивным ядром.

Главный экран должен говорить:

> Сегодня не надо читать всё. Нужно сделать один ясный шаг и проверить, понял ли ты идею.
