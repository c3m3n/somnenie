# Repository Hygiene

Этот документ фиксирует новый стандарт работы с репозиторием. Старую историю не переписываем ради косметики: пустые PR и смешанные коммиты остаются историческим долгом, но новые изменения должны идти по правилам ниже.

## Что считаем грязной историей

- PR без описания.
- PR с названием вроде `redesign`, `cleanup`, `misc`, если внутри несколько несвязанных задач.
- Коммит, который одновременно меняет UI, домен, README и CI.
- Сообщение коммита с `and`: чаще всего это две задачи.
- Попутный рефакторинг рядом с багфиксом.
- Удаление файлов без объяснения, как проверено отсутствие регрессий.

## Что считаем хорошим PR

- Одна задача, один понятный результат.
- Описание отвечает на вопросы: что, зачем, как проверялось, какие риски.
- Изменения можно откатить без потери другой работы.
- Если менялся UI, есть ручная проверка или скриншоты.
- Если менялась доменная логика, есть тесты и объяснение причины.

## Когда нужен отдельный PR

Отдельный PR нужен, если изменение относится к разным причинам:

- багфикс и визуальный редизайн;
- рефакторинг и изменение поведения;
- обновление зависимостей и новая функция;
- изменение контента курса и изменение приложения;
- настройка CI и правка runtime-кода.

## Когда можно объединять изменения

Объединять можно только тесно связанные изменения:

- код и тест для одного бага;
- компонент и его локальные стили;
- README и шаблон, если оба описывают один процесс;
- миграция storage и тесты этой миграции.

## Как писать описание PR

Минимум:

```md
## Что изменилось
- ...

## Зачем
- ...

## Как проверялось
- npm run quality

## Риски
- ...
```

Пустой body означает, что контекст потерян. Такой PR не мержится.

## Как писать commit message

Используйте префиксы:

- `feat:` новая функциональность;
- `fix:` исправление бага;
- `refactor:` структура без смены поведения;
- `docs:` документация;
- `test:` тесты;
- `chore:` инфраструктура, зависимости, уборка;
- `ci:` GitHub Actions / pipeline.

Примеры:

```text
fix: block locked quiz route
docs: document repository hygiene
test: cover localStorage migration skip cases
chore: add issue templates
```

## Что делать с уже грязной историей

Не переписываем `main` ради косметики. Force-push ломает ссылки, PR-контекст и чужие локальные копии.

Если нужен исторический контекст, добавляем:

- ADR в `ADR.md`;
- заметку в `docs/repository-hygiene.md`;
- отдельный decision log, если решений станет много.
